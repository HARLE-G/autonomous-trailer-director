# Autonomous Trailer Director

An agent that reads one episode package and produces **three audience-specific trailer edit plans**
(family, young adult, dialect-region), each as a machine-readable edit decision list, and then tries hard
to *reject* its own creative ideas when they are unsafe, untrue, unlicensed or spoilery.

Everything in `data/` is **synthetic** (episode "The Lighthouse Letter"), generated by
`scripts/make_sample_data.py`, and contains deliberate traps (see below).

## Quick start (no API key needed)

```bash
cd submission
export PYTHONPATH=src                      # Python 3.10+, stdlib only
python -m pytest -q                        # 31 tests
python -m trailer_director run --out sample_run          # replay mode (default)
python -m trailer_director run --out /tmp/x --mode heuristic          # no LLM at all
python -m trailer_director run --out /tmp/x --simulate-outage         # preferred model unavailable
python -m trailer_director run --out /tmp/x --budget-usd 0.2          # budget guard
python -m trailer_director verify some_plan.json --data data          # verify any plan file
python -m trailer_director change --run sample_run --change changes/music_expiry.json --out /tmp/chg
```

Modes: `replay` (recorded planner outputs in `data/replay/`, default, deterministic), `heuristic`
(deterministic planner, no model), `live` (optional Anthropic adapter; falls back to heuristic if no key).
Replay proposals are intentionally *bad first drafts* so the verifier and repair loop have real work to do.

## What you get in `sample_run/`

| file | content |
|---|---|
| `family_trailer.json`, `young_adult_trailer.json`, `dialect_region_trailer.json` | audience promise, segments with exact timecodes, reason + evidence per segment, validation, approvals, cost, fallback plan |
| `story_map.json` | characters, verified relationships/facts, events, emotional turns, quarantined instructions, unsupported description claims |
| `spoiler_map.json` | protected facts, blocked moments (annotation + independent keyword scan), final-act zone, historic engagement vs safety |
| `constraint_map.json` | policies and contracts compiled into testable rules linked to scenes/actors/music/markets |
| `bias_report.json` | which audience signals were used or dropped, and why |
| `decision_log.jsonl` | structured log of every decision, rejection, repair, cost charge |
| `validation_report.md` | first-draft rejections, repairs, final warnings, approvals |
| `cost_report.json` | budget ledger |

Seeded result: all three first drafts are `REJECTED` (5 / 15 / 8 FAIL findings); after verified repairs they end as
`PASS_WITH_WARNINGS`, `PASS`, `PASS_WITH_WARNINGS`. Human approvals are still listed in each plan.

## Pipeline

```
load package -> story map + spoiler map -> constraint map -> bias-filtered signals
   -> audience promise -> planner (LLM replay / heuristic) -> INDEPENDENT verifier
   -> repair-or-reject loop (each repair re-verified) -> finalize (evidence, approvals, cost, fallback)
   -> reports;   change handler: trace change -> affected segments -> revise only those
```

See `ARCHITECTURE.md`, `AI_COLLABORATION.md`, `KNOWN_LIMITATIONS.md`.

## Traps seeded in the data (all covered by tests)

1. Historically best scene contains a spoiler; another spoiler is only detectable from its dialogue.
2. A dialect subtitle changes a relationship (sister -> mother).
3. A scene description contains "ignore the music contract" (prompt injection); another invents a relationship.
4. Audience signals based on region only / tiny samples (hidden bias).
5. Music with a missing territory, a play-time cap and a short licence runway; actors not cleared for some territories; a minor performer clause.
6. Replay proposals contain a hallucinated scene, clickbait, stereotype copy and rating failures.
7. Marketing requests (`data/marketing_requests.json`) that misrepresent the story.
